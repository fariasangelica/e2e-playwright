# e2e-playwright

A repository for beginners starting with [Playwright](https://playwright.dev). It covers introduction, getting started, running tests, writing tests, debugging tests, and running tests on CI.

## What this project does

Playwright E2E suite on **Chromium**, **Firefox**, and **WebKit**, with GitHub Actions CI.

| File | What it covers |
| --- | --- |
| `tests/example.spec.ts` | Smoke tests on [playwright.dev](https://playwright.dev): page title + "Get started" navigation to Installation |
| `tests/test-1.spec.ts` | Contoso Traders shopping flow (recorded with Codegen): search Xbox → open product → add to bag → assert cart |

Setup command used:

```bash
npm init playwright@latest --yes -- --quiet --browser=chromium --browser=firefox --browser=webkit --gha
```

## Setup

## Tests in this repo

### `example.spec.ts` — starter examples

Uses built-in locators with auto-wait/retry and role-based selectors (preferred over CSS/XPath):

1. **has title** — opens playwright.dev and asserts the title contains `Playwright`
2. **get started link** — clicks `getByRole('link', { name: 'Get started' })` and asserts the `Installation` heading is visible

```ts
await page.getByRole('link', { name: 'Get started' }).click();
await expect(page.getByRole('heading', { name: 'Installation' })).toBeVisible();
```

### `test-1.spec.ts` — Contoso Traders flow (Codegen)

Generated by interacting with the page (`npx playwright codegen` / Pick locator), then kept in the suite. Flow:

1. Go to `http://cloudtesting.contosotraders.com/`
2. Search for `xbox` via `getByPlaceholder`
3. Open the Xbox Wireless Controller product (`getByRole('img', ...)`)
4. Increase quantity (`+`), click **Add To Bag**, open cart (`getByLabel('cart')`)
5. Assert the product is visible in the cart

Locators used here: `getByPlaceholder`, `getByRole`, `getByLabel` — user-facing APIs with auto-wait/retry.

## Running tests

```bash
npx playwright test                         # all tests, headless (default)
npx playwright test tests/example.spec.ts   # one file
npx playwright test --headed                # visible browser
npx playwright test --ui                    # UI Mode
npx playwright show-report                  # HTML report
```

| Mode | Behavior |
| --- | --- |
| **Headless** | No browser window (default) |
| **Headed** | Browser window visible (`--headed`) |

## Debugging

Configured in `playwright.config.ts`: `trace: 'on-first-retry'`.

```bash
npx playwright test --debug     # Playwright Inspector
npx playwright test --ui        # step-by-step UI Mode
npx playwright show-report      # open report / traces after retries
npx playwright show-trace trace.zip
```

Playwright is strict by default: a locator must match **one** element. Use breakpoints + `--debug` to pause and inspect.

## CI

On every push/PR to `main` or `master`, `.github/workflows/playwright.yml`:

1. `npm ci`
2. `npx playwright install --with-deps`
3. `npx playwright test`
4. Uploads `playwright-report` as an artifact

If a test fails on the PR, fix it before merge.
